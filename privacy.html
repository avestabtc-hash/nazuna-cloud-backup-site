Privacy Policy

This policy describes how the personal utility Nazuna Cloud Backup uses Google Drive access granted through OAuth 2.0. It applies to the backup workflow only. This website consists of static HTML and CSS with no forms, scripts, or analytics, and collects no information from visitors.

Last updated: 6 November 2026

1. What Google Drive data is accessed

The tool requests the single Google Drive scope drive.file. That is the per-file scope: it permits access to files created by this tool and to files the owner explicitly opens with it. It does not permit browsing or reading the rest of the owner's Drive.

  • File contents of the specific files the owner backs up or restores.
  • File metadata needed to transfer and compare those files, such as names, sizes, modification times, and Drive file identifiers.
  • No Gmail, Contacts, Calendar, Photos, or other Google account data is requested. No additional Google scopes are requested beyond drive.file.

2. Why access is required

Google Drive is the storage destination. Without the drive.file scope, rclone cannot create backup files in the owner's Drive or read them back for a restore. The scope is used only for those backup and restore operations.

3. How files are transferred and stored

  • Transfers happen directly between the owner's computer and Google Drive through Google's API over HTTPS, initiated by an rclone command the owner runs.
  • Backed-up files remain in the owner's own Google Drive account, in the folder the owner chooses. The project has no separate copy.
  • No file passes through a server operated by this project. There is no application server, database, or third-party storage service in the workflow.
  • Storage and at-rest protection are those of the owner's Google Drive account. This tool does not add, and does not claim, any additional encryption layer or security certification.
  • Integrity checking uses SHA-256 checksums computed locally on the owner's machine, not Google Drive metadata.

4. How OAuth credentials are protected

  • Authorization is performed through Google's OAuth 2.0 consent screen. The resulting access and refresh tokens are stored in the rclone configuration on the owner's local computer.
  • The configuration file holding those tokens lives on that machine under its operating system account and file permissions. The tokens are not published on this website, not embedded in these pages, and not committed to this repository.
  • No client secret or token is transmitted to, or stored on, any server operated by this project.

5. Data retention and deletion

  • Backed-up files persist in the owner's Google Drive until the owner deletes them. There is no automatic retention period imposed by this project.
  • To delete backup data, remove the files or the backup folder from Google Drive. To remove local copies of transfer state, delete the relevant local files on the owner's machine.
  • To remove the authorization material, delete the rclone configuration entry that holds the token, and revoke access as described below.
  • This project retains no copy of the owner's files and therefore has nothing of its own to delete.

6. Revoking Google account authorization

Access can be revoked at any time from the owner's Google Account permissions page at myaccount.google.com/permissions. Removing the Nazuna Cloud Backup entry stops the token from working. Deleting the corresponding local rclone configuration removes the stored token from the machine. Revocation stops future transfers; it does not delete files already stored in the owner's Drive.

7. No selling of personal data

No personal data is sold, rented, shared, or disclosed to third parties. The project has no commercial data flow.

8. No advertising or profiling

There is no advertising, tracking, analytics, behavioral profiling, or audience measurement on this website or in the backup workflow. This site loads no third-party scripts, fonts, or trackers.

9. No AI model training on Google user data

Google user data obtained through the drive.file scope is not used to train, fine-tune, or evaluate any AI or machine learning model. The workflow does not send file contents to any AI service.

10. Contact for privacy inquiries

Privacy inquiries can be submitted publicly through the issue tracker of this project's repository: github.com/avestabtc-hash/nazuna-cloud-backup-site/issues. No private email address is published on this site. Because the issue tracker is public, do not post file contents, tokens, or other private information there.

Scope note. This policy describes the intended rclone and Google Drive workflow. It makes no claim of legal certification, regulatory compliance, or Google OAuth verification. Verification and domain approval, if any, are separate decisions made by Google in Google Cloud Console.
